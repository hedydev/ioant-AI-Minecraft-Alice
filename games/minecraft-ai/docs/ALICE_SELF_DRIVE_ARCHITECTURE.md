# Alice AI — 自我驱动 / Goal-driven autonomy（2026-10-20）

## 用户目标与现场证据

用户亲眼看到 Alice 从房间走出后，在外面长时间站着；要求 Alice 主动、有目的地生活，而不是只能执行一次命令。
2026-10-20 Bedrock 真机日志进一步证明：
- Alice 执行木门脱困：`[-1261,98,653]` 发现木门 `[-1261,98,655]`，两次短程门后移动；第二次 `door_passage_local_only_server_unverified`，不等于服务端自位置确认。
- 之后房间扫描中心移到 `[-1256,98,651]`；`reachableCells` 从 18 到 91，`openFrontier` 有 `[-1257,98,645]`；从另一侧返回旧门的路线达 10 格。**这是更开放局部空间的观察证据，不是「已到室外」的单独证明。**
- 旧决策反复 `FIND_ROOM_EXIT` → `WAIT` → `FIND_ROOM_EXIT`：门在 6 格扫描范围内就持续被当作任务，不区分它已在身后以及是否有更广阔的安全空间。
- 进入 dusk/night 后 `safeToExplore=false`，`scout_server_endpoint_unconfirmed` 又产生 `motion` 区域冷却；睡床失败后重复采木，树叶=0、建筑木板证据强。
- 玩家能够看到走动，但底层 `movement_evidence` 仅把**来自服务端的自玩家位置纠正包**计为直接服务器证据，频繁返回 `no_two_server_positions`。缺失纠正包不是「服务器没有走动」的证明，亦不能把本地位移直接称作服务器确认。

## 关键缺陷

旧逻辑是一次性状态选择：`LEARN_WEAPON→WORK` / 失败标记 cooldown / `SCOUT` / `WAIT`。没有一个跨评估周期持续跟踪目标、场景转移和完成条件的高层意图；`WAIT` 把缺少目标、夜晚防护、不可验证位置及真正安全待命混为一谈。

**正确设计是两层自治**：
1. **认知/目标层（不能发包、不能写世界）**：感知当前场景与需要；选择多步、持久且可验证的动机/目标；记录先前行动与证据可信度。
2. **执行/安全层**：现有路径、门、床、采集、合成、战斗适配器执行短时、可取消的真实动作；安全与人类意图永远高优先级。

## 目标优先级（目标与实际执行许可严格分离）

1. **生命安全（硬抢占）**：死亡/低血/近身危险，现有 `safetyTick` 独占动作；无法证明安全时不冒进。
2. **人类指令**：STOP、FOLLOW、GUARD、聊天任务；自动意图不能夺取它们的移动权。
3. **维持生存**：有食品则安全进食、装备升级、夜间优先尝试可到达的床；不可到达/不能入睡必须记住位置与原因，不要无休止重试。
4. **获取资源**：确有资源不足才发起采集；树木识别必须有自然树证据（日志 93 原木/0 树叶附近玩家房屋不得拆）。
5. **探索/学习**：使用可证明通行的 3D 地形图，偏好新的局部前沿/生物群落/自然地面；短段移动→记录实际效果→重新观察。
6. **安全观察/计划**：夜间没有安全目标、位置可信度不足、未知地形时，可以等待但必须持有可恢复目标和清楚原因；不以随机行走充当自驱。

## 已实现（阶段 A：可观察的目标驱动语义）

- `bedrock-native/experiment/src/self_drive.cjs`：纯只读 `sceneFromSurvey()` 使用 `openFrontier`、`reachableCells` 和门证据将场景分为 `door_limited_area` / `open_local_area` / `limited_or_unknown` / `unobserved`。开放区域阈值 32 个观察到的可达格、至少一个已知前沿；仅属于**局部空间判断**。
- `selectDrive()`：若玩家已尝试同一木门且看见广阔已知前沿，不再把门当作必须解决的全局目标。日间保留安全 `SCOUT`，将高层目标标为 `DISCOVER_RESOURCES`；夜间、无安全移动时标为 `PREPARE_DAYLIGHT`，不发明夜间盲走。真正封闭空间且门可执行时仍保留 `FIND_ROOM_EXIT`；无可验证门的房间是 `OBSERVE_ROOM` 而不是声称找到出口；等待服务端运动证据是 `VERIFY_MOVEMENT`。
- `SelfDriveJournal`：会话内的当前目标、目标转移、执行反馈（`confirmed` / `unverified` / `blocked`），仅在目标变化时发 `[Alice drive] goal transition:`，在当前高层自主任务完成时发 `[Alice drive] task feedback:`。**这是当前进程内的 goal journal，尚未持久化成跨重启的目标计划。**
- `runtime.cjs` 接入选目标并检查旧 survey 的**坐标邻近 + 25 秒新鲜度**，旧门不应吸走开放区域夜间待命意图。角色 `状态` 查询会显示当前 drive goal。夜间 PREPARE_DAYLIGHT 每约 15 秒重新获得只读自主评估资格，保留普通安全控制器频率。
- 10 个独立纯策略测试覆盖：用户现场 91 格/旧门 10 步、夜间观察、白天优先新资源、室内安全近门优先、门未知不拦截独立安全探索、动作可信度不足停动、目标转移去重、任务确认/不确认区别。隔离 JS 验证通过；**完整 Mac/Mint Node24 `npm test` + BDS 真实场景仍未验收**。

## 绝不能直接照搬的“智能”捷径

- 不因为 `openFrontier` 就谎称已经在室外：只是局部观察到安全通道，可能是巨大建筑内部。
- 不因为本地 `position` 改变就标记服务器确认，甚至基于不存在的两个纠正包关闭/放开硬安全许可。
- 不让 LLM 直接生成挖墙、破坏玩家建筑、任意坐标飞行或任意 API 调用；LLM 只提出结构化建议，实际行为由确定性验证执行器接管。
- 不以延长 `forward` 毫秒、无界随机漫游、强行夜跑来掩盖缺少可靠位置和碰撞证据。
- 不自动执行原先禁止的建造/箱子访问/睡陌生玩家床位；需明确策略及所有权约束。
- 不增加全天候固定高频模型调用；仅重大目标切换时才请求高层规划，底层反射与执行仍是确定性本地逻辑。

## 后续阶段（尚未实现）

**B. 可靠世界模型 / 位置真值**：统一客户端预测位移、Bedrock 自玩家纠正包、BDS `querytarget` 只读实测与物理碰撞。为每条位置赋予 `source/confidence/freshness`；修复 `no_two_server_positions` 对确实在游戏里走动的误读，不冒进自我证明。

**C. 真正的目标分解与长程路线**：例如「准备木剑」→「找天然树林」→「走过可验证的安全边界」→「砍合法原木」→「捡起并核实背包」→「合成」→「装备」；每一步成功、失败、证据不足都可重规划，旧木门/旧失败路线只用于避障与短期学习，不变成永久执念。维护大小受限的拓扑图和已访问区域；只沿已知危险度可接受路线移动。

**D. 连续生存行为**：健康/饥饿/背包容量/时间/附近玩家与敌对生物/天气形成动态优先级；夜间寻找已有安全避难所、装备检查及定向观察；如果不能证明安全才待命，并记录明确下次唤醒条件。不能空喊观察而实际没行动。

**E. 经验记忆**：把已确认的资源点、危险点、路径失败原因、玩家指示与重复工作记录为可过期的领域知识，不能仅根据一次本地预测便永久奖励一个技能；需要安全的本地 JSON / SQLite 原子写入、受限大小、私密文件权限、可撤销规则。

**F. 规划模型 + 确定性执行**：本地 Gemma/Ollama 只看无个人密钥的观察摘要，可提出 2–3 个合法且有优先级的候选目标；执行器依然根据地形、装备、安全预算和用户命令决定是否实际操作。若模型离线或错误，基本生存/探索仍正常工作。
